# 儿童知识库：产品、技术与交互设计

日期：2026-09-25。目标：家长能在 App 中增加和纠正知识，孩子的问题得到可靠、完整的讲解，检索不拖慢原有对话。

## 竞品参考与本产品取舍

| 公开一手资料 | 借鉴点 | 本产品实现 |
| --- | --- | --- |
| [Intercom Knowledge snippets](https://www.intercom.com/help/en/articles/8074407-create-and-manage-snippets) | 管理短知识条目、选择是否用于回答 | 一张知识卡片围绕一个核心问题，可编辑、发布、停用 |
| [Dify Knowledge Pipeline](https://dify.ai/rag) | 检索测试、内容元信息与知识管理 | 家长输入孩子的问法，看到命中内容、回答版本和依据 |
| [NotebookLM 使用介绍](https://blog.google/innovation-and-ai/products/notebooklm-beginner-tips/) | 回答关联具体资料与引用 | 家长可见来源，孩子语音只讲答案，不朗读链接 |

这些是公开说明的功能参考，不是竞品性能实测。当前小模型已经出现事实与类比错误，首版明确匹配的知识问答直接使用审核后的内容，避免每次用模型重新编写事实。陌生问题不强行套用相似条目。全文文档自动切分、联网搜集、向量服务和模型重新训练不在首版关键路径；支持在编辑器粘贴整理后的资料。

## 功能与内容

- 家庭服务器共享一套知识卡片，所有绑定家长可管理，儿童端没有编辑权限。
- 内置 30 张原创编写的儿童百科卡片，附公开教育机构来源，覆盖自然天气、地球太空和身边科学；允许家长编辑、停用和删除，不在重启时覆盖或复活已改动的条目。
- 家长新增卡片可选择“儿童百科”或“家庭知识”，填写核心问题、相似问法、标准讲解、简短版、详细版、分类、年龄范围与来源。核心问题和标准讲解发布必填；百科还需要来源说明。
- 保存草稿与发布分开。编辑已启用条目时旧发布版本继续提供答案，保存新草稿不改变孩子问答；发布必须确认当前内容，使用版本号避免两个家长互相覆盖。
- 停用立即移出检索，删除二次确认。已删条目不参与任何后续问答。已发给设备、正在播放的一段语音不远程撤回，遵循端侧停止逻辑。
- 家长可试问已发布知识，也可试问当前编辑草稿；草稿试问不发布、不写孩子偏好或对话记录。
- “再详细讲讲”“简单一点”等明确追问复用当前知识卡片。每轮重新检查发布状态，修改、停用、删除后不会从旧会话继续吐出旧答案。
- 知识问答证据包含卡片 ID、发布版本、问题和来源；普通孩子语音不播报管理信息。

## 问答行为

1. 停止、休息、资源点播、权限和已有危险请求检查保持最高优先级。图片及视觉对象追问、游戏和原创故事不被百科检索抢占。
2. 规范化标点、大小写和有限的礼貌前后缀，保留否定、颜色、数字和实义词。核心问题及家长填写的相似问法精确匹配才直接回答。
3. 关键词倒排查找候选，近似百科匹配仅用于家长试问提示，日常问答继续回答原问题，避免把“鱼在水里呼吸”引向“船浮在水上”。近似家庭知识先澄清，孩子回答“是的”后再次检查对应卡片的启用状态与年龄再讲解，回答“不是”则请其重新完整提问，不把“蓝色”和“绿色”等近似问句视为同一个事实。多个有效条目匹配时要求澄清，避免任意选择来源。
4. 默认讲标准版；明确要求简短时使用简短版（未填则取标准版首句）；明确要求详细、或年龄较大时使用详细版（未填则使用标准版）。“表达简单”设置使用标准版，仍可显式要求详细。
5. 知识库未命中的普通问题继续本地模型路径，知识库不是问题白名单。模型先解释可靠的已知部分，具体标注未知细节，不用“问爸爸妈妈”替代整个回答；不编造实时数据、私人信息或联网经历。已停用卡片的明确追问仍返回不可用说明，不从旧正文继续生成。管理预览只检索卡片，不调用模型。相似问法可由家长补充，逐步提升召回率。

首版选择高精度优先。自由问法覆盖不等于语义搜索能力，不声称能回答任意百科追问。所有预设与回归问题要包含相似但不同的问题，测试拒绝误匹配。

## App 信息架构与交互

入口：家长首页“知识库”卡片、设置中的“知识库”。复用当前圆角分组、字体、主色、暗色主题和底部操作区域。

列表页布局：

```text
‹ 知识库                         新增
给孩子准备可靠、听得懂的答案
[搜索问题或分类                   ]
[全部] [已启用] [草稿] [已停用]
[试问知识库]
天气与自然 / 为什么会下雨？
内置百科 · 已启用 · 有未发布修改   ›
家庭生活 / 我们什么时候读书？
家长添加 · 草稿                  ›
```

编辑页：核心内容优先展示。核心问题、标准讲解为主表单；相似问法每行一条，支持系统粘贴；“更多讲法”和“分类与来源”分组收纳简短版、详细版、年龄、来源。显示字数上限，保存前校验必要字段并显示中文错误。固定底部“保存草稿”“预览发布”。顶部返回和系统返回共用未保存修改确认；网络错误不清空输入。

预览发布：展示孩子实际会听到的标准讲解、简短/详细版切换、来源和年龄。家长勾选确认后点击“发布并启用”。未保存内容先保存，再发布准确的返回版本；中途冲突保留本地输入，提示返回列表重新读取，不自动覆盖。

试问页：输入孩子的问法 → 显示“命中知识 / 需要说得更具体 / 暂无匹配”，命中时显示实际答案、来源和检索耗时。草稿试问明确标注“仅当前草稿”；全库试问仅使用已启用且适龄的发布内容。发布/停用操作有明确成功反馈。

无内容、无搜索结果、未连接服务器、加载中、保存失败、版本冲突均有中文反馈。控件最小触控高度 48dp；内容随键盘滚动，底部操作不遮挡输入；不要求家长理解 token、向量或检索阈值。

## 技术设计

### 存储与发布

新增 `knowledge_cards` 表：`id` 主键，`version` 乐观锁，`origin` 来源类型，`state` 生命周期，`draft` JSON，`published` JSON（含发布版本），`updated` 时间。沿用 SQLite WAL 与现有事务，不改动原资源表。内置卡片使用稳定 ID，`INSERT OR IGNORE` 初始化。删除保留无正文墓碑以阻止重新播种。

独立 `knowledge.py` 提供模型、CRUD、检索索引与 API，`data/knowledge-seed.json` 为随包分发内容。应用初始化加载已发布卡片构建索引；任何发布、停用、删除在写锁内提交事务并替换不可变快照，完成后再响应。草稿更新不改变当前问答快照。索引不是原文唯一副本，重启可重建。

知识检索只访问内存中的规范问题字典、按卡片 ID 字典与双字词倒排索引。无需网络、embedding、额外模型进程和逐次 SQLite 扫描。候选数有上限，近似匹配额外设 4ms 计算预算，超长问题不做模糊扩展；整个查询以本机 p95 < 10ms 为目标，1000 条卡片压测。命中时在进入对话模型信号量前返回，可在模型繁忙时回答。普通寒暄只有一次字典查找和轻量意图判断，不遍历全库。

### API

- `GET /v1/knowledge`：家长列表，搜索与状态筛选。
- `POST /v1/knowledge`：创建草稿。
- `GET /v1/knowledge/{id}`：详情、编辑草稿与当前发布版。
- `PUT /v1/knowledge/{id}`：携带 `expectedVersion` 保存草稿。
- `POST /v1/knowledge/{id}/publish`：版本检查与内容确认，发布。
- `POST /v1/knowledge/{id}/disable`：停用。
- `DELETE /v1/knowledge/{id}?expectedVersion=…`：删除并失效索引。
- `POST /v1/knowledge/preview`：家长全库/单草稿试问，无模型调用。

CRUD 和预览都依赖已有家长鉴权；机器人通过 `/v1/turns` 获取适龄发布答案。标准调试会话也走知识匹配，提示词草稿试聊保持独立，避免让知识直答掩盖提示词测试效果。草稿及正文不能成为系统指令。暂不收集未命中问题到持久数据库。

### 会话与一致性

知识回答存入现有临时会话的 history，并记录本轮知识卡片 ID，沿用十分钟超时与会话数量上限。旧卡片停用或删掉后明确追问返回说明；新事实问题重新检索，不无限沿用上一次主题。知识内容写回操作清掉相关知识会话的正文历史，保留卡片引用供明确追问检查，避免旧正文继续进入模型上下文。通用删除记忆仍能清理这些临时会话。

备份需包含知识卡片与删除墓碑；恢复家长知识为草稿，不能自动发布未经本次确认的旧内容。内置内容采用稳定键防重复；仅从未编辑过的内置初始卡允许由备份草稿替换，其他已有卡片不覆盖。App 恢复后的索引更新必须经过同一刷新路径。电脑 CLI 恢复应在停服期间进行，完成后启动服务重建索引。

## 开发与验收

先完成服务端数据、索引、预设和 API，再接入问答与备份，最后开发 App 列表、编辑、预览发布和试问。按实际集成调整细节并更新本文。

验收覆盖：身份边界、草稿不泄漏、修改发布即时生效、版本冲突、删除重启不复活、年龄筛选、相似问题不误答、知识追问、原控制/视觉/游戏路径、模型忙时知识直答、未命中降级、备份恢复；对 1000 条知识测 warm lookup 与 API 耗时。App 自测完整新增→草稿→试问→发布→修改→停用→删除流程，检查返回提示、键盘和亮暗主题截图。完成 Python 回归、Android 编译与相关设备测试，报告真实命令与结果。

## 2026-09-25 问答兜底修正与联网建议

原先把所有科普未命中都转成固定拒答，导致 30 条预设之外大量问题无法进入模型。本次取消这一问题白名单，并把“不确定时回答已知部分”的规则追加到每轮文本系统提示中，覆盖已保存的家长模板；安全拦截增加原因解释。天气、温度、空气质量等明确实时请求在无数据源时直接说明能力限制，避免模型编造实时情况。没有增加额外模型请求或外网调用。

本地 `qwen3.5:2b` / `4b` 声明支持工具调用，但当前服务只调用本地 Ollama，没有联网搜索能力。工具调用能力不等于搜索已接入，也不代表小模型可以准确判断自己是否说错。若增加联网核实，建议由服务端执行有限检索：已审核知识优先，普通知识本地回答，时效性问题或明确要求核实的问题在家长开启后检索；仅提交去除个人信息的公共主题，不提交家庭私事、历史对话、声音或照片。

检索必须有总超时、缓存、并发上限、结果长度上限和来源筛选；超时直接说明本次未完成核实并解释稳定的已知部分，不无限等待。网页内容作为不可信资料隔离，不能成为系统指令；来源和时间在家长界面可追溯。检索有助于提供证据，不能保证模型整理时绝不出错。家长审核后的常用内容可再存入本地知识库。本次未实现或启用该联网链路。

官方依据：[Ollama Web search](https://docs.ollama.com/capabilities/web-search) 提供需要 API key 的云端搜索与网页读取接口；[Tool calling](https://docs.ollama.com/capabilities/tool-calling) 说明工具需由宿主程序执行。生成回答可以留在本地，搜索请求仍属于向外部服务发送数据。
