# 唤醒反馈与倾听交互设计

日期：2026-09-23。状态：唤醒与触摸核心交互已实现并完成模拟器定向验证；真机声学验收待补。设计目标与实现边界见第 10 节。

目标：孩子叫“小伙伴”或轻触机器人脸部后，立即看到它醒了、听到它回应，并能明确判断现在是否可以继续说；轻抚和揉脸有短促、顽皮的互动。沿用全屏纯脸、隐藏家长管理、30 秒续聊和 10 分钟会话上限。

## 1. 推荐体验

孩子：“小伙伴。”

机器人：眼睛迅速睁开、眉毛轻抬，亮度恢复，微笑着说“我在。”；真实声音驱动嘴形。说完收嘴，保持睁眼注视，轻轻歪头，等待孩子继续。

孩子：“给我讲个故事。”

机器人：倾听时保持专注；确认说完后视线上移，进入思考；开始实际播音时才张嘴。回答结束收嘴，重新倾听，30 秒内可以直接接着说。

孩子连着说“小伙伴，给我讲个故事”时，立即出现睁眼反馈，短确认音承担声音反馈，省略完整问候，优先保留用户首句。若“我在”已经开始，目标是检测到有效用户发言后尽快让出话轮；此能力必须通过目标手机的回声与双讲测试。

## 3. 状态表现

| 状态 | 眼睛、眉毛和姿态 | 嘴形与声音 | 退出条件 |
| --- | --- | --- | --- |
| 可唤醒待机 | 半睁、低亮、低频眨眼，轻微视线漂移 | 小弧嘴，安静 | 有效唤醒 |
| 刚被叫醒 | 迅速睁大、双眉轻抬，回到正面注视，平滑恢复亮度 | 微笑；播“我在”时按音频张嘴 | 回应结束或用户已发言 |
| 等你说 | 睁眼，瞳孔居中；入场轻歪头约 2° 后保持，不能不停摇摆 | 收嘴，不持续播音 | 检测到发言、超时或退出 |
| 正在听你说 | 保持注视，轻微抬眉；真实语音活动可触发克制的眼部亮度变化 | 保持收嘴，不用嘴巴模拟用户音量 | 检测到句末 |
| 思考 | 视线略向上、一侧眉抬起，与倾听可区分 | 收嘴；等待超过约 2 秒可说一次“我想想”，快速回答则不播 | 回答就绪、失败或取消 |
| 回答 | 自然睁眼与眨眼 | 按真实播放进度和音频包络张合；静音段收嘴 | 实际播放结束 |
| 回答后续听 | 迅速回到“等你说”，仍保持清醒 | 不重复“我在”或“还有什么事” | 下一句或 30 秒无有效输入 |
| 返回待机 | 放松眉眼，短暂合眼后恢复半睁，平滑降低亮度 | 一次轻柔结束音；不追加长告别 | 等待下次唤醒 |
| 麦克风关闭／使用受限 | 稳定闭眼，眉嘴姿态与可唤醒待机不同 | 按已有家长策略保持静音 | 设置或限制解除 |
| 故障 | 清醒但疑问眉、琥珀色辅助提示；不能只靠颜色区分 | 能播放时说明具体原因；不能播放时保持故障脸 | 恢复或进入管理 |

正常机器人屏幕仍只有脸，不增加文字状态、按钮、声波面板或字幕。降低动态效果时去掉歪头和弹动，保留睁眼／收嘴／视线差异。没有方向估计时保持正面注视，不表现成已经定位到了说话人。

## 4. 语音文案与选择规则

默认推荐“我在。”，日常备选“在呢，你说。”、“我听着呢。”。采用同一角色音色，常用句优先，连续两次避免同一句，保持语气稳定，不需要每次随机扮演不同性格。

“有什么事呀？”、“怎么啦？”可作为低频亲切表达。“有什么吩咐？”偏管家风格，“干啥呀？”容易因语调显得不耐烦，适合家长主动选择的俏皮风格，不放进儿童默认回应池。

- 独立叫名：一次简短口头回应，建议成品时长 0.5～1.2 秒。
- 叫名后紧接问题：短确认音即可，不用完整问候与用户抢话。
- 正在倾听时连续叫名：短时间重复命中不重启会话、不重播整句；一次轻抬眉即可确认仍在听。
- 回答结束的自然续聊：直接恢复倾听，不重复唤醒欢迎语。
- 正在播放故事时叫名：先暂停并保存位置，立即转入唤醒／倾听，不让故事和回应叠播。
- 服务离线但本地唤醒可用：仍能本地回应，再简短说明“我现在连不上，可以听下载好的故事”；不能假装可以正常联网回答。

家长设置提供“语音回应（默认）／短提示音／仅表情”，并可试听。反馈音量跟随明确配置，默认不能为零；用户主动选择零音量或仅表情时尊重设置，不偷偷提高系统音量。麦克风关闭与扬声器静音分别展示和配置。

## 5. 时间目标与话轮规则

以下为待实机验证的工程目标，以应用收到本地有效唤醒事件为起点，不能等同于从用户开始叫名计时。

| 项目 | 建议目标 |
| --- | --- |
| 第一帧可见唤醒反馈 | P95 ≤ 150ms |
| 完成睁眼与抬眉过渡 | 约 180～250ms |
| 开始可听反馈 | P95 ≤ 400ms；测实际声音起点，包含素材前置静音 |
| 音频播放结束后回到倾听姿态 | ≤ 150ms；同时确认采音已就绪 |
| 用户开始说话后停止正在播的开场回应 | 目标 ≤ 200ms，需回声／双讲验证 |
| 无有效输入等待 | 保留已确认的 30 秒，从可接收用户语音且机器人播放结束后计时 |

唤醒视觉立即发生。可在约 120～180ms 的短窗口判断用户是否继续发言，决定播完整短句还是短确认音；具体窗口结合 KWS 延迟调整，不能因此延迟首帧反馈。

唤醒后应立即保护首句音频，不能仅靠播音结束后的固定两秒回看保障所有情况。开场播放与采音并行需要回声控制，不能把机器人的“我在”识别成用户输入，不能用自身播音延长等待时间。语音活动指示应来自处理后的真实输入；未就绪时只显示“正在醒来”，不能假装正在听。

若目标设备的自然插话未通过验证，仍需完整保存并处理紧跟昵称的首句，使用更短的确认音降低干扰。任意播报阶段的自然插话作为单独能力验证，现有“再次叫昵称打断”继续保留。

停止、进入后台、麦克风关闭、使用限制等事件立即取消声音和动画对应的旧任务。任何旧回调不得把已关闭会话重新切回倾听。

## 6. 现有实现核查与落地点

核查对象是工作区源码和资源，尚未确认用户手机所安装 APK 与此版本一致。

1. `scripts/generate_prompts.py` 已定义 `wake: 我在。`，`assets/prompts/wake.wav` 存在。读取结果：单声道、16-bit PCM、24kHz、约 975ms，非全零采样。此检查不等于确认设备可听见，也不替代音色试听。
2. `RobotRuntime.wakeFrom()` 已调用本地 `localPrompt("wake", ticket)`。因此“没有声音”的确切原因仍需核查是否触发唤醒、使用限制、系统与 App 音量、音频焦点、输出路由和实际播放错误。
3. `RobotRuntime.tick()` 没有给 `SessionState.OPENING` 独立映射，通常落入 `standby`。`MainActivity` 又会将待机亮度设为 0.15，开场阶段可能仍显得暗且没醒。
4. 开场播放未把状态改为 `SPEAKING`；`RobotFace` 仅在 `speaking/story/song` 下按 `mouth` 张嘴，因此开场即使有声音，也不会按其真实音量展示说话嘴形。
5. `performanceUntil` 的表演优先级高于倾听、思考等状态，唤醒也没有清除旧表演。旧大哭或大笑可能遮蔽业务状态。唤醒时应中止旧表演；交互状态优先，情绪只作不影响辨识的附加表现。
6. `input.captureSpeech` 只在 `LISTENING/FOLLOW_UP` 开启，`openingFinished()` 在提示音结束后执行。虽然已有两秒 `WakeAudioBuffer` 补偿首句，仍需验证播音混入、截断以及自然插话，不应宣称“立刻开始识别”已经实现。
7. 现有倾听脸已有更大的眼睛，但缺少专门的开场过渡和稳定的等你说姿态；不能只靠放大一点眼睛来表示完整状态转换。

建议改动集中于现有文件：`RobotRuntime.kt` 管理声画同步、优先级、播放失败与反馈策略；`RobotFace.kt` 增加唤醒姿态和过渡；`AudioInput.kt` / `WakeAudioBuffer.kt` 保障首句与回声处理；`Session.kt` 明确开场、倾听就绪、取消和超时语义；家长声音页增加回应模式。回应素材本地预置／预加载，不依赖服务端或大模型即时生成。

本地音频资源损坏时可退化为原创短提示音；音频焦点被拒或输出路由不可用时，备用音也可能无法播放，必须保留可见反馈并在管理诊断记录失败阶段，不能把“调用了播放”算作成功。

## 9. 触摸叫醒与顽皮互动补充

用户认可前述唤醒设计，并补充希望触摸脸部也能叫醒睡眠中的机器人，或触发“哎呀，好痒”等声音与动作。本节将触摸作为正式互动入口；本次实现与验证范围见第 10 节。

### 9.1 竞品依据

- [EMO 官方产品说明](https://living.ai/emo/)介绍了头顶触摸传感器和摸头互动，以及表情、动作和拟声反馈。借鉴“触摸能直接获得角色回应”。
- [Eilik 官方产品说明](https://www.energizelab.com/eilik/)明确将触摸互动与丰富情绪、面部表情联系起来，并描述其顽皮性格。借鉴“触摸方式不同，角色反应也有变化”。

来源查阅日期 2026-09-23。以上官方页面不证明它们都使用“触屏揉脸说好痒”或相同的睡眠唤醒规则；以下分区、手势、中文文案及时间参数是本 App 的原创适配方案。手机触屏不假设能判断按压力度。

### 9.2 推荐手势与反馈

| 操作 | 推荐表情和声音 | 完成后 |
| --- | --- | --- |
| 待机／浅睡时轻点脸部一次 | 先抬一下眼皮，迅速睁眼，视线朝触点稍偏再回正；说“嗯？我在呢。”或“我醒啦，你说。” | 收嘴，进入真实倾听 |
| 待机／浅睡时轻轻划过额头 | 眼睛短暂弯成笑弧，眉毛放松，脸朝轻抚方向偏一点；轻声“嘿嘿” | 本次即算触摸唤醒，睁眼进入倾听，不再叠加“我在” |
| 待机／浅睡时在脸颊来回轻揉 | 一侧眼睛先眯起，脸轻轻躲开，再笑一下；说“哎呀，好痒！”或“嘿嘿，痒痒！” | 结束短表演后睁眼倾听，不再次播问候 |
| 清醒且空闲时轻点／轻抚 | 眨眼、微笑或轻抬眉，保持清醒；默认无声 | 维持当前会话，不重启 |
| 清醒且空闲时揉脸 | 一次短笑脸与“好痒”反馈；用户一开口就优先听 | 回到倾听，不重置会话上限 |
| 用户正在讲话、助手思考或播报时触摸 | 至多给一个不遮蔽工作状态的小眼神；不播逗趣语音 | 当前问答或故事继续 |
| 双击 | 立即按已有暂停语义停止声音与表演；不追加撒娇声 | 保留原暂停后的会话行为 |
| 右上角长按 2 秒 | 进入已有 PIN 管理流程，不触发逗趣回应 | 管理页 |

这里的“睡眠”指 App 在前台可交互的待机／浅睡。家长禁用时段、达到使用上限、麦克风关闭和手机锁屏属于不同状态，触摸不解除限制、不授予权限；受限时可短暂动一下眼皮示意收到触碰，但保持受限姿态和既有静音策略，不进入倾听。不能承诺隔着系统锁屏触摸就唤醒 App。

首触唤醒优先做到确定、简短。默认轻点使用清晰的叫醒语；“好痒”主要交给揉脸，孩子能逐渐理解动作与回应的联系。正常使用页仍不出现触摸按钮、热区边框或说明文字；在首次引导和家长帮助中说明手势。

### 9.3 动作节奏与趣味强度

- 手指按下时，目标 100ms 内给眼皮／视线的轻反馈，不等服务器。此时仅作视觉预反馈，尚未确认手势，不开始播音或开启新的会话采集。
- 揉脸表演建议总长 0.8～1.5 秒，最多轻轻左右偏转两下，幅度约 2～3°；不要剧烈抖屏、闪光或长时间闭眼。松手后自然回正，动作有上限，不随手指停留无限循环。
- 嘴形随真实笑声或台词变化，不播放声音时使用静态微笑。素材本地预置，统一角色音色，与普通回应保持相近响度，不用突然尖叫表现惊喜。
- 使用“哎呀，好痒！”“嘿嘿，痒痒！”等短句即可。避免摸一下就哭、指责孩子、表示受伤或要求继续陪伴。
- 趣味语音建议至少间隔 5 秒，同一手势最多触发一次，不排队；冷却期只保留克制视觉反馈。新一次合法唤醒所需的确认反馈不被趣味冷却吞掉。
- 触摸唤醒后沿用语音唤醒的 30 秒等待和权限策略；会话内轻抚／揉脸不反复重置等待、不延长 10 分钟上限。自身笑声不算用户发言。超时发生在表演中时，以退出会话为准。
- “减少动态效果”模式去掉摇摆，保留眉眼和声音；“仅表情”模式不出声。家长可关闭逗趣语音而保留轻点叫醒。

### 9.4 手势冲突与触摸区域

快速连点已经承担“双击暂停”，不再用快速连点触发“好痒”。揉脸采用一个手指持续接触、在脸颊范围内来回滑动，与双击区分。

将一次手势完整判定为轻点、轻抚、揉脸、双击或管理长按之一，不能同一次操作先说“我在”，又笑，又弹管理页。沿用平台双击时间窗口：首触先有可撤销的视觉反馈，确认单击后才提交唤醒和语音；第二击命中时取消待发的单击动作，立即暂停。触摸出声延迟包含手势判定时间，单独度量，不直接套用语音唤醒的 400ms 目标。

首版判定初值：超过系统 touch slop 后取消轻点候选；额头区域一段明显滑动视为轻抚；脸颊区域累计滑动约 48dp 且至少一次方向反转视为揉脸。参数需根据目标屏幕和儿童操作验证。揉脸一旦识别不再转成长按；未达到滑动条件的按住，不自动重复触发轻点。多指、系统取消和从屏幕外滑入不触发互动。

面部热区覆盖额头、眼睛、脸颊和嘴周围的宽松范围，按实际角色布局映射到横竖屏，不要求精确点到瞳孔，也不把整块屏幕留白视为脸。额头和脸颊分区影响反应方式，轻点各部位均可叫醒。视线跟随的是已知触点，不代表视觉识别了用户。

右上角管理长按区域优先处理：按住期间不播撒娇语音、不启动轻抚；确认长按后取消本次触摸候选。双击暂停继续覆盖现有可操作画布，不能因为新增面部热区而缩小兜底范围。

### 9.5 状态协调与实现落点

当前 `RobotRuntime.touch()` 仅在允许使用、未静音且处于 `STANDBY` 时设置 1200ms 的 `happy` 表演，并不调用唤醒，也不播放触摸回应。`RobotFace` 的单击回调没有向运行层传递触点位置，尚无轻抚或揉脸识别。

建议在 `RobotFace.kt` 将触点、区域和手势类型传给运行层；在 `RobotRuntime.kt` 让确认的待机触摸走统一唤醒流程，记录来源为触摸，按本次手势只选择一段开场回应。手势识别与会话规则解耦，避免在绘制代码中直接开启相机、麦克风或发网络请求。

逗趣是短时表达层：可在待机或空闲续听时显示，不能抢占有效用户发言、思考、播报、停止或受限状态。处理后的有效用户发言出现时，取消逗趣声画并恢复倾听；只有通过回声／双讲验证后，才开放续听期间的逗趣语音，否则该状态只做无声微表情。新会话、语音唤醒、暂停、进入管理或后台，都取消旧的触摸动画／音频；结束回调按当前会话代际检查，不能恢复过期状态。

### 9.6 新增验收与本次检查

| 场景 | 预期 |

| 待机轻点脸部 | 首触有视觉反馈，单击确认后有一次短回应，真实进入倾听 |

## 10. 实现与验证结果（2026-09-23）

已实现：语音与触摸走统一唤醒流程；开场睁眼和真实音频嘴形；本地三句轮换回应、触摸回应、轻抚笑声、揉脸“哎呀，好痒”；开场期间保护首句并用会话代际拒绝旧输入；连说时优先短提示音；倾听、有效发言、思考和说话分别呈现；慢回答只提示一次“我想想”；30秒无输入用短提示音结束；家长端支持语音／短提示音／仅表情与顽皮回应开关、试听；受限、暂停、后台优先取消互动。

新增的手势识别器统一处理单击、拖动、双击、长按，额头滑动和脸颊揉动按实际脸部区域判定。单击等待系统双击判定窗口，按下时先有视觉预反馈；双击不再叠加单击唤醒。隐藏管理仍在右上角长按2秒。

有意保留的设备验证边界：连续对话中的轻抚／揉脸使用无声短表情，避免未经验证的自然双讲打断用户；尚未宣称任意播音期间自然插话、儿童声学唤醒成功率或反馈延迟P95已达标。开场采音继续保留首句，硬件AEC可用时启用，并对首轮已知提示语回声进行保守过滤；这不能替代目标手机的回声与双讲验收。

首轮使用 Kokoro 素材，随后已换为 Qwen3-TTS 1.7B / Serena / gentle 生成的10段本地语音，提示音保留160ms。Qwen版已重新核查APK素材、格式、前置静音与峰值，并通过2项模拟器回归（59.271秒，包含真实30秒退出）。“在呢，你说”1931ms、“嗯，我在呢”1471ms超过1.2秒建议值，待真机试听评估节奏；物理声学、回声和双讲仍需设备验收。
