# 本地语音合成与语气控制

默认使用 **Qwen3-TTS 12Hz 1.7B CustomVoice 的 MLX 8bit 版本**。这是语音合成模型，和 Ollama 的 `qwen3.5:2b` 对话模型各司其职。运行时只加载磁盘权重，不访问云端 TTS。当前适配器面向 Apple Silicon Mac。

## 安装与启动

先按服务 README 安装主环境，再在仓库根目录执行：

```sh
bash scripts/bootstrap_tts.sh
python3 scripts/install_tts.py
# 官方站无法访问时可选择镜像，仍使用同一固定 revision 和内容哈希：
python3 scripts/install_tts.py --endpoint https://hf-mirror.com
ROBOT_TTS_BACKEND=qwen3-mlx ai-service/.venv/bin/robot-service --data runtime serve --bind 0.0.0.0
```

Python 3.12 的 TTS 依赖单独装到 `ai-service/.venv-tts`，不升级 ASR 环境。模型下载约 3.08GB，建议为模型及独立环境预留至少 6GB；安装脚本支持断点续传和逐文件哈希校验。完整源文件和哈希在 `scripts/tts-model.lock.json`，安装完成后生成 `installed.json`。

`ROBOT_TTS_PYTHON` 可指定另一个已安装依赖的 Python **绝对路径**；`ROBOT_MODELS` 可指定模型根目录，下载时相应传 `--models`。安装需要联网，之后推理子进程设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` 和禁用 Hugging Face 遥测，只传本地模型路径。默认不会在缺少 Qwen 时静默回退到其他声音。

## 家长端操作

进入“声音”，选择中文、英文和原创故事音色，分别设置回答语气、故事语气。提供自然、温柔陪伴、轻快开心、讲故事、睡前舒缓五种预设；可填写最多 200 字补充描述，例如“耐心、温暖，像一起探索世界的朋友”。使用同一段文本点“试听回答语气”和“试听故事语气”，满意后保存配置并下发到机器人。

默认中文使用 Serena，英文使用 Ryan。Vivian、Uncle_Fu 也适合试听比较；Dylan、Eric 本身带地域口音，不建议作为普通话学习的首选。旧配置的 `zh-girl`、`zh-boy`、`en-us`、`en-gb` 自动映射到新音色，不要求清空家庭配置。

资源编辑页可以独立设置朗读音色、故事语气和描述。资源试听与实际资源合成使用同样的 `story=true` 路径。**已发布版本及其缓存音频保持原样**；修改资源声音后重新发布，生成新版本的音频。全局声音配置用于即时回答和原创故事，不覆盖资源自己的声音设置。

发布快照同时保存 `ttsProfile`（引擎、模型 revision、推理库和渲染版本），旧记录缺失此字段时按原 Kokoro 处理。服务切换后仍可返回旧版本已缓存的音频；缺失段落若需要另一个渲染版本，则返回 409 并提示重新试听/发布，避免同一版本混用两种声音。恢复原引擎也可继续生成它的缺失段落。

手机已完整下载的版本保持原声，离线时不会自动换声。普通重新发布允许当前旧快照读完，下一次在线点播使用新版并从头开始，不套用旧位置；旧离线文件仍保留到家长完整下载新版本，下载中途不得把部分文件当成完整资源。只有下架或删除才按撤回同步清理。仅改全局音色或重启服务不会重写离线文件，自带上传音频也不会被TTS替换。

当前版本是 CustomVoice：支持预置音色和语气指令，未接入声音克隆或任意生成新音色。语气是模型生成偏好，不能保证每次结果完全相同；“语速偏好”通过指令实现，不能当作精确的 0.7/1.3 倍音频处理。发音仍需用实际孩子常听的内容验收，多音字可使用项目已有发音纠正功能。

## 接口与替换引擎

`robot_service/tts.py` 定义 `TTSProvider`，只接受 `SynthesisRequest`（正文、音色、语言、语速偏好、语气、补充指令），返回 `SynthesisResult`（PCM16 WAV 字节、时长）。业务路由不导入 MLX 或 sherpa 的推理 API。

```text
Android / 资源朗读 → intelligence.speech → 单一 tts_worker
                                          ↓ TTSProvider
                                     QwenMLXProvider
                                     KokoroProvider
```

正文和 `instruct` 分开传入 Qwen；语气描述不拼入朗读正文。一个服务进程只持有一个 TTS 子进程/模型实例，试听、实时回答、资源合成都复用它。ASR 有独立进程。TTS采用有界优先队列：已经开始的一段推理完成后，按对话回答、当前资源播放/试听、后台批量准备的顺序调度，同级请求按到达顺序执行。总等待最多8项，其中后台最多4项，为对话保留排队空间；对话最多等10秒，图书合成／家长试听最多等1秒，超时或队满返回429。取消和超时请求会退出队列，推理仍最多90秒，超时销毁子进程以便下次重新加载。不会中途打断正在执行的模型推理，也没有音频流式传输；因此队列优先不等于保证首句延迟达标。Android对话按句请求并预取下一句；图书发布后自动提前生成音频，朗读时预取下一段，支持重启恢复和失败重试。参见[图书音频准备与连贯播放](图书音频准备与连贯播放.md)，实际端到端延迟仍须在目标设备验收。

立即换回原有 Kokoro：

```sh
ROBOT_TTS_BACKEND=kokoro ai-service/.venv/bin/robot-service --data runtime serve --bind 0.0.0.0
```

需要先安装原有 Kokoro 权重。此时服务使用主 Python 环境，能力目录不再声明语气/指令支持；家长端据能力隐藏相关选项，保留已保存设置。引擎切换需重启服务。

接入第三种引擎时，实现一个 `TTSProvider` 适配器，在 `tts.py` 的工厂、音色映射、能力目录及模型路径中注册，配置所需的独立 Python 环境。保持 `/v1/speech/preview`、`/v1/speech/reply` 和资源音频 API 不变。`GET /v1/models` 返回 `ttsInfo`，包含引擎、模型、文件就绪状态、音色、语气和功能标志；文件就绪不等于运行时健康，实际合成失败仍返回 503。

更换权重、推理库版本或语气模板时同步更新 `render_profile()` 的指纹；不要在保持旧指纹时改变渲染行为。

## 即时提示音

唤醒、安抚、休息等短句预先合成并打包到 APK，因此离线且无需等待电脑。修改全局声音不会重新生成这些静态提示。重建方式：

```sh
PYTHONPATH=ai-service ai-service/.venv/bin/python scripts/generate_prompts.py
# 只重建一条：在命令后加 wake 等名称
```

脚本使用同一 TTS 接口，保留原创文案、去除边缘长静音，并写入 `assets/prompts/provenance.json`。重建后重新打包安装 APK；`chime` 为算法生成的原创双音。

## 验证范围

实际开发机器为 **Apple M4、32GB 统一内存**，不能将其速度视为 M1 16GB 的测量结果。固定依赖中的 MLX 二进制还受 macOS 版本约束；以锁定依赖可安装的系统为准。M1 16GB 的全链路等待时间、同时运行 ASR/对话模型的内存压力仍需在目标机器测量。

服务定向测试：`ai-service/.venv/bin/python -m pytest ai-service/tests/test_tts.py ai-service/tests/test_intelligence.py -q`。真实模型试听和构建结果在本次集成记录中单列，不用 mock 测试代替音质验收。
