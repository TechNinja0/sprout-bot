# 工程维护手册

本手册对应开发中的 `0.1.0-dev`。产品意图见 docs/01—11；具体实现进度和未完成验收见 [需求追踪](需求追踪.md) 与 OpenSpec `build-family-robot/tasks.md`。未完成项不能据此宣称可面向儿童正式发布。

本机诊断、脱敏报告字段、单项遗忘和相机提示音的维护规则见[诊断与记忆撤回实现说明](诊断与记忆撤回实现说明.md)。优先收集脱敏报告；不要把资源库备份或运行目录上传到公开 issue。

取图意图、结构化视觉输出和对象追问的失效规则见[视觉请求与对象追问实现说明](视觉请求与对象追问实现说明.md)。更换视觉模型前先用相同素材比较，不能只根据参数量决定，也不能把下载完成当作验收通过。

## 工程边界

| 工程 | 职责 | 不承担的职责 |
| --- | --- | --- |
| `android-app/app` | 同 APK 双身份、PIN/Keystore/TLS、家长管理、机器人纯脸、单录音KWS、相机与真实播放、离线副本 | 不持有模型供应商密钥，不直接控制电机 |
| `android-app/core` | 单调时钟会话、时间安排、累计使用、成长策略 | 不依赖 Android，普通 JVM 可测 |
| `ai-service` | 身份/配置/资源库、OCR/ASR/TTS、本地模型路由、备份墓碑 | 不替代手机立即停止，不通过云端兜底 |
| `motion-firmware` | 独立运动安全决策核心及主机测试 | 尚无实际 MCU 固件，不能称作硬件验收 |
| `protocol` | API边界、固定唤醒材料 | 不包含家庭凭据 |
| `runtime`、`.artifacts`、`.tools` | 私有运行数据、模型、验证证据/工具 | 不提交开源仓库（Android 正式签名材料 `runtime/android-signing/` 除外） |

手机负责当下是否可以录音、看图、发声；服务端负责内容处理与资源事实。即使服务器迟到、断网或大模型返回控制语句，手机仍检查会话代际、前台状态和使用安排。模型文本没有直接改变配置、发布资源或调用电机的权限。

## 开发环境与初次安装

推荐 JDK17、Android SDK36、Python3.12（服务支持3.11—3.13，模型安装脚本需3.12的安全解包接口）、macOS Apple Silicon。Gradle Wrapper固定8.11.1；AGP/Kotlin及Android依赖固定在各 `build.gradle.kts`。Linux可运行服务和Tesseract OCR，当前实际模型性能证据来自Apple Silicon，不预设其他平台速度。

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
bash scripts/bootstrap_service.sh
ai-service/.venv/bin/python scripts/install_models.py
android-app/gradlew -p android-app :app:assembleDebug
```

`bootstrap_service.sh` 建虚拟环境、按锁文件安装并在macOS编译Apple Vision OCR。Linux自行安装 Tesseract 的 `chi_sim`/`eng` 数据；MP3/M4A验证使用锁定的PyAV，无需另装ffprobe。所有格式仍接受同样上传大小和页面限制。图片OCR使用系统框架时不会将原稿发送至云端；采用其他OCR适配器必须重新审查出站行为。

模型下载由 `scripts/models.lock.json` 指定URL和SHA256。权重、AAR不随Git分发；KWS模型装到APK资产前保留来源和许可材料。当前ASR使用 faster-whisper 1.2.1 + 固定的 Systran/faster-whisper-small，只加载本地文件；sherpa-whisper在中文多字节输出上出现丢字，保留证据但停用。锁文件 `asr` 对应当前 CTranslate2 small 权重；`asr-small` 是早期 sherpa ONNX 对比模型，`asr-base-comparison` 是此前 CPU base 对比权重，均不作为当前默认。Apple Silicon 可选择已锁定的 MLX 加速后端；CPU 为跨平台默认。MLX 必须先经过 Silero VAD，无人说话时不调用 Whisper，避免静音生成文字。手机上传最多30秒，因此使用单窗口解码复用语言检测与转写的音频编码；不强制中文，保留中英自动检测。Android支持arm64-v8a/x86_64，发布到其他ABI需另行构建验证。

## Apple Silicon 可选识别与启动预热

在本机 macOS 26.2、Apple M4/32GB 实测；旧版 macOS 和其他型号不能直接套用性能数据。先安装基础依赖，然后：

```sh
ai-service/.venv/bin/pip install -r ai-service/requirements-apple-lock.txt
ai-service/.venv/bin/python scripts/install_models.py --only asr-mlx
ROBOT_ASR_BACKEND=mlx ROBOT_PRELOAD_MODELS=1 ai-service/.venv/bin/robot-service --data runtime serve
```

`ROBOT_ASR_BACKEND=cpu` 使用 faster-whisper small；`mlx` 使用本地8bit large-v3-turbo。锁文件将上游 `model.safetensors` 保存为引擎约定的 `weights.safetensors`，内容哈希不变。缺少文件或依赖时明确报错，不静默联网下载或切换云模型。

`ROBOT_PRELOAD_MODELS=1` 用项目原创短句在内存预热 ASR/TTS/LLM，并用内存生成的纯色小图预热 VLM 图像编码；不读取家庭图片。`/health` 的 `modelWarmup` 为 `warming/ready/failed`，默认未开启时为 `disabled`。预热期间其他模型请求可能返回忙；失败后检查模型安装。语音预热有90秒上限，文本/视觉各次预热有60秒上限；预热不是性能验收。两种对话模型最后调用后均请求驻留30分钟，显存压力仍可能导致卸载，首次安装/重新加载的耗时单列。退出服务释放语音 worker，Ollama 为独立进程。

## 本地对话模型

2026-09-23已比较统一4B方案，修复安静模式教学问句后复测仍有文字速度差距，当前继续保留双模型；内存收益与暂不切换原因见[单模型合并评估](单模型合并评估.md)。该比较主动停止了上一轮长测，旧接续观察记录不能当作仍在运行。


macOS arm64可以安装固定Ollama归档，不修改全局开机启动：

```sh
ai-service/.venv/bin/python scripts/install_models.py --only ollama-macos-arm64
bash scripts/run_ollama.sh
# 另一个终端
OLLAMA_HOST=127.0.0.1:11435 .tools/ollama/ollama pull qwen3.5:2b
OLLAMA_HOST=127.0.0.1:11435 .tools/ollama/ollama pull qwen3.5:4b
ai-service/.venv/bin/python scripts/verify_llm.py
```

普通文本使用2B，带图请求使用4B；模型角色固定在 `robot_service/local_models.py`，清单分别为 `models.lock.json` 的 `llm`/`vlm`。`verify_llm.py` 校验两者清单、配置与全部模型层；缺少4B时视觉能力单独显示未就绪，不能拿2B已安装代替，也不自动切云端。4B选择依据及冷/热态记录见[视觉实现说明](视觉请求与对象追问实现说明.md)。升级或回滚时需把源码、两个模型清单与权重一起核对，不能只替换标签。

运行绑定127.0.0.1:11435并设置 `OLLAMA_NO_CLOUD=1`，API同样不使用系统HTTP代理访问本机模型。LLM标签可能变化，清单验证不通过必须停止并审核，不能悄悄更新锁文件。ASR在独立子进程驻留；当前Qwen版本的对话TTS、图书音频和家长试听共用一个TTS子进程。当前推理段完成后对话优先，同级先进先出；对话最多等待10秒，后台最多等待1秒，总等待8项、后台最多4项，超时或队满返回429。旧Kokoro版本独立后台TTS进程的隔离结论不能用于当前版本。单模型不抢占执行中的推理，仍需验证真实并发延迟和内存，见OpenSpec任务9.5及《本地语音合成》。TTS 90秒、ASR 60秒硬超时；超时会销毁对应子进程，下次请求重新加载。本地LLM/VLM也限制单并发和60秒总等待；模型缺失/忙/超时均返回明确错误，不捏造回答。手机按句播放回答并预取下一句；首句耗时与完整回答耗时分别记录。

## 家庭服务启动与手机连接

macOS 日常后台启动、局域网地址与运维命令见[家庭局域网启动指南](家庭局域网启动指南.md)。已配置电脑可运行 `bash scripts/home_service.sh start`，无需 ADB。

先确定手机可达的局域网IP/主机名，电脑与手机同网。没有公网需求时不需要购买域名。

```sh
ai-service/.venv/bin/robot-service --data runtime init --host 192.168.1.20
ai-service/.venv/bin/robot-service --data runtime serve --bind 0.0.0.0
```

初始化生成服务ID、自签TLS证书和私钥、恢复秘密、两分钟连接材料 `runtime/connection.json`。手动把连接材料导入手机机器人身份，核对家庭电脑来源并设置管理PIN；不要把材料贴到issue或常规日志。连接码过期后运行 `invite --host ...` 重发，旧码不会被延长。局域网监听是显式命令，不自动更改路由器、防火墙、端口转发。

机器人管理页生成家长配对材料；家长手机导入后，仍需在机器人本机确认请求。家长令牌独立，可逐台撤销。证书指纹在手机加密保存；地址变更可以沿用受信证书身份，证书变化必须重新取得本地可信材料，不能忽略TLS错误。

开发真机可使用 `adb reverse tcp:8765 tcp:8765` 配合 `https://127.0.0.1:8765`，这只证明USB联调，不等同家庭Wi-Fi连通验收。

## 家长配置与儿童使用

初始推荐：Asia/Shanghai、每天20:00—次日09:00禁用、连续媒体30分钟、每日额度不设限、英语零基础、安静为主。按年龄基准日期增长表达深度；不因生日升级英语阶段，不自动改变相机、出站或时段权限。

家长修改配置先带 `expectedVersion` 发送，在线心跳15秒以内才接收，指令10秒内有效，机器人ACK后展示生效。并发冲突先刷新，离线不积压临时唤醒/播放/放行。微小时间变更通过服务时间重新校验；系统大幅改时、重启时钟不可信时先阻止儿童使用，联网校时或管理员处理后恢复。

机器人本机是即时限制执行者。待机只有本地KWS；会话音频才上传家庭电脑ASR。昵称需2—6个汉字且通过模型词表校验，更改昵称应重新实测误唤醒。停止、暂停、页跳转是端侧有限命令；ASR/LLM故障不能影响双击暂停。不要声称一个成年人/合成样本能够验证儿童唤醒。

机器人界面以表情为主，下方显示状态符号和简短中文提示，不展示对话正文。右上角长按2秒、PIN后进入管理；后台立即取消播放并释放相机/录音。屏幕常亮只在机器人界面活动期间启用。CameraX只保留最新小图于内存，实际新帧超过1秒会等待，最多等2秒，过期不发模型。

## 资源库工作流

1. 家长新建图书/故事/儿歌/英语短句草稿，填写版本、语言、来源与适龄范围。
2. 上传封面及内页图片、TXT/Markdown、可选文字或扫描PDF；单文件32MB，图书最多300页，单页2万字符。
3. 后台解析生成未审核页面。逐页看原图、修正文、页码和页序；失败可重试，取消后重试采用新作业ID，旧结果不能覆盖新草稿。
4. 保存正文后试听，再确认完整/节选范围、逐页审核与试听状态，发布固定版本。改正文/声音/页序会使旧试听确认失效。
5. 孩子说“读这本书”，封面OCR匹配标题/别名/ISBN，只有已发布版本可读；草稿仅返回不可读原因。同名最多两候选可口头选择，更多候选请补充ISBN或交家长选择。封面不会推导整本内容。
6. 原文按固定段落TTS，版本锁定；发音映射独立于原文。儿歌优先提供原音频，普通TTS不能替代歌唱合成。
7. 需要离线时发起“下载到机器人”，全部音频和manifest校验完成才可离线点播。离线不承诺封面OCR或自由对话。下载失败临时文件不当作可播放资源。
8. 下架/删除优先同步撤回，离线设备显示待同步；只有联网清理后才可声称该设备副本已删除。新版本与旧版本隔离，撤回后旧版本不可自动复活。

目录 `runtime/assets` 存家长原稿；SQLite存元数据、版本和索引；`runtime/audio/<revisionId>`存生成音频，可重建。SQLite的标题/别名/ISBN与正文就是当前结构化知识库，不必先建设向量数据库；问答模型不能越过已审核书籍直接生成“原书正文”。

## 备份、恢复、升级与回滚

```sh
ai-service/.venv/bin/robot-service --data runtime backup /private/path/family-library.zip
ai-service/.venv/bin/robot-service --data runtime restore /private/path/family-library.zip
```

资源ZIP带内容哈希，包含正文、原稿、记忆状态、删除墓碑等，不含设备令牌、TLS私钥或音频缓存。恢复不覆盖现有资源；恢复为待审核草稿，记忆回到待确认，云端权限关闭，墓碑阻止旧内容复活。恢复不是“重新发布全部旧内容”。手机备份导出可以保存到用户选择的私有位置；手机恢复单包最多32MB，资源ZIP工具限制512MB。超过512MB改用停服后的完整runtime加密备份。

安装身份灾备是另一件事：停服后把完整runtime（排除可重建models/audio）加密备份到私有位置，包括SQLite WAL/SHM处理后的数据库、server.key/server.pem和recovery.secret；不要用普通资源ZIP替代身份灾备。恢复秘密离线单独保管。若凭据泄露，备份恢复不能代替撤销与重新绑定。

PIN或机器人身份恢复由电脑本地管理员发起：

```sh
ai-service/.venv/bin/robot-service --data runtime recover --robot <机器人ID> --host <局域网地址>
```

导入两分钟恢复材料时，服务轮换机器人令牌并撤销全部家长绑定、未完成配对和待执行指令。家长随后重新绑定。初期若PIN阻止进入连接页，可在系统设置清除本App数据再导入恢复材料；此操作会清除手机离线副本，不清除电脑书库。

升级前保存版本号、代码提交、依赖锁和上述备份；停服后换代码/虚拟环境，运行测试再启动。数据库当前schema=2，首次启动自动从1增加jobs.options；不认识版本则拒绝启动。升级前停旧服务并备份数据库，不允许旧服务继续写已迁移的作业表。迁移必须逐版本、可备份、不可静默降级。回滚代码需搭配同代数据库备份；不能把新schema直接交旧代码打开。Android回滚可能需要提高versionCode或卸载重装，先确认离线副本可重新下载且恢复材料可用。

## 排障与验证

| 现象 | 检查 |
| --- | --- |
| APP连接失败 | HTTPS地址、手机同网/USB reverse、服务监听、防火墙、连接码是否过期 |
| 证书不匹配 | 停止连接，电脑检查server.pem身份；重新取得本地材料，不关闭证书校验 |
| 已发送但未生效 | 在线心跳、ACK、配置版本、10秒有效期，刷新后重试 |
| 不响应昵称 | 当前禁用时段/静音/系统权限/温控；KWS zipformer2、资产哈希、实际儿童声学测试 |
| 看不到书 | 相机权限、有效会话、新帧、封面文字是否清晰、资源已发布且版本一致 |
| 朗读缺字或读错 | 对照原稿与发布原文、发音词表、实际音频；不要只根据ASR回读定论 |
| 导入失败 | 文件格式、OCR/PyAV安装、32MB/300页限制、磁盘至少256MB余量 |
| 下架后离线仍可见 | 设备尚未联网；查看下载状态pending_removal，联网完成撤回清理 |
| 模型忙/超时 | 模型目录完整性、Ollama127.0.0.1:11435、RAM与CPU；禁止自动云兜底 |

```sh
bash scripts/check.sh
ai-service/.venv/bin/python scripts/model_smoke.py
```

普通单测使用临时目录和测试身份，不读取家庭书籍。真实模型自测生成原创封面和混合PDF，验证OCR、发布、原文音频、VLM等；这是模型集成证据，不是10本实体书、儿童30次唤醒或24小时稳定性验收。真机测试APK只用于调试，不能随正式APK发布。发布前严格按照 [发布检查](发布检查.md) 完成未验证项。

## 播放与真机回归补充

MP3/M4A使用[MediaCodec](https://developer.android.com/reference/android/media/MediaCodec)流式解码后交AudioTrack，PCM WAV也使用AudioTrack；没有引入Media3播放栈。两者嘴形均使用实际PCM采样RMS，不依赖机型是否支持Visualizer，长音频不整首展开为内存PCM。失去音频焦点时暂停，焦点回来不自动续播。旧播放器焦点回调不可暂停后来启动的音频。

本地短提示（唤醒、未听清、断网）来自本项目原创文字，由锁定Kokoro生成，离线可用；脚本`ai-service/.venv/bin/python scripts/generate_prompts.py`可重建。后台/禁用/双击仍可以立即取消提示音。昵称词表更新替换旧唤醒词，固定资产仅保留停止等有限命令。

家长在资源编辑页可以查看作业状态、取消和重试导入；重试前先保存草稿，等待完成后再校对。播放清单只接受已发布资源，切换下一项时再次校验，整个清单不能突破媒体时限或禁用时段。断网只点播已完整下载的资源；配置和阅读进度按服务ID及机器人ID隔离，连接另一个家庭服务不会混用旧缓存。

真机调试使用已授权的测试手机和临时身份：

```sh
ai-service/.venv/bin/python scripts/test_huawei.py --serial <ADB序列号> --adb <adb路径>
ai-service/.venv/bin/python scripts/test_huawei.py --serial <ADB序列号> --adb <adb路径> --class-name AudioPolicyTest
```

## 摘要与纯脸反馈

家长摘要显示最近90天使用时长、仍保留播放进度的资源类别数量、待审核偏好数，以及当前机器人登记期间的问答/媒体/下载失败和连接中断次数。计数存于手机加密配置，通过心跳同步；离线显示最后同步值，重新登记清零。服务不收集这些失败的对话原文。删除资源后对应类别不再统计，计数不代表学习效果。

正常待机为弯曲闭眼、月亮和「休息中」，用轻微呼吸、伸缩小口水和上浮淡出的 Zzz 表现无声睡眠；唤醒为睁大眼和光芒；聆听为青色大眼、麦克风和侧边声波；语音识别、思考、视觉观察分别使用文字线条、环绕光点、取景框；准备声音使用沙漏，播放动效跟随实际PCM音量。静音、使用限制、暂停和故障分别显示斜线麦克风、锁、双竖线和害羞红脸蛋／重试符号。限制期间额头另有醒目的锁头：休息时段显示月亮和「休息时间到了」，每日额度用完显示时钟和「今天先玩到这里」，继续遵守原有家长限制与临时放行规则，减少动态效果模式保留轮廓与文字。

等待阶段持续10秒开始显示耗时，30秒提示「等待有点久」；播放位置10秒不前进提示「播放暂未推进」。这只是状态提示，不更改会话时限、不自动停止播放；真正超时/服务忙/播放失败时显示错误与处理建议。界面本身若因主线程冻结而无法刷新，不能靠界面动画诊断，需要系统日志。允许使用且待机时，轻点、轻抚额头或揉脸进入统一唤醒流程，按相机权限开启会话并按所选模式回应；对话错误后触摸也可重新唤醒。连续对话中的趣味触摸只作无声短表情。双击暂停和右上角长按2秒进入管理优先处理。

状态反馈参考 [Alexa 注意力状态指南](https://developer.amazon.com/en-US/alexa/voice-interoperability/design-guide/baseline-guidance) 和 [Google Nest 状态灯说明](https://support.google.com/chromecast/answer/7073219?hl=en-CA)，只借鉴区分聆听、思考、说话的原则，表情与符号为项目实现。

## 容量保护

服务端正文素材与派生音频共用10GiB软上限，可用 `ROBOT_LIBRARY_MAX_BYTES` 在启动前调整；默认至少保留256MiB磁盘空间。新上传、生成音频和备份恢复均检查容量，写文件使用原子替换，容量不足返回507；不会自动删除家长资源。恢复中途失败会一起回滚新文件和数据库记录。模型下载及解包另检查剩余空间，模型/备份/日志不计入上述内容库额度，维护者应按磁盘实际空间管理；不承诺限制系统其他应用写入。手机离线缓存上限1GiB，写入锁内复核容量和256MiB余量。

`ai-service/.venv/bin/python scripts/test_permissions.py --serial <已授权测试机> --adb <adb路径>` 验证相机/麦克风OS权限撤销后冷启动及恢复，结束恢复原权限。`ThermalSafetyTest` 注入Android框架SEVERE状态验证采集/播放停止，finally执行reset；这不是实际发热实验。

断网刚发生时心跳可能仍显示在线，资源清单和分段音频在传输失败后会尝试已完整校验的离线副本；分段必须与当前阅读版本一致。HTTP权限/撤回拒绝、证书错误不回退，避免用旧副本绕过服务端明确决定。

短游戏为本地规则互动：孩子主动请求颜色、数数或猜谜后，最多三题、两分钟，错误或听错只示范一次，不连续要求纠错。随时停止，换话题退出，不记录成绩或推断能力，不要求持续打开相机。原创故事仍由独立开关控制，三题小游戏不等于开启自动编故事。

完成状态 `completed-awaiting-analysis` 只表示全部阶段执行结束，维护者仍须核对时长、失败日志、内存增长、温控与原产品阈值后更新验收。脚本直接送入原创合成录音，因此不能替代儿童唤醒、真实声学回声和背景误唤醒验收。

若宿主ADB命令意外结束，先保存原日志并查询 `adb shell pidof org.familyrobot.app`、`adb shell dumpsys activity` 中该应用的 `ActiveInstrumentation`、手机私有目录的 `files/stability-mixed.jsonl` 或 `files/stability-standby.jsonl`。宿主套件标记失败不代表手机测试已经停止；原PID和采样仍推进时不要安装APK或启动第二份测试。ADB服务重启可能同时丢失 `adb reverse` 转发。确认是原测试后，可接续观察：


观察器持有同一长测锁，校验原始开始事件与源码/APK指纹，只采集原测试的新记录及主机资源；确认原PID后恢复缺失的USB转发，不启动或终止手机测试。状态在 `.artifacts/development/endurance-observer.json`，证据写入原目录下独立 `observer-*` 子目录。ADB查询失败只记观察失败，不能当作应用崩溃。观察超过3分钟无进展时退出并保留现场，仍不停止手机进程；再次操作前必须核实手机是否还在运行。

原宿主失败日志不能改写。观察器的完成状态也只表示待分析，必须另外核对混合完整14400秒或待机完整86400秒、同一进程、末尾complete/failed、采样连续性、断网区间、主机观测缺口和最终清理情况；缺少原instrumentation终端结果时明确披露并补强证据，不能只凭一个状态文件勾选全部通过。原套件终止后不会再自动启动下一阶段，须先分析接续结果，再由跟进任务启动未执行阶段，避免重复占用同一手机。

### macOS ADB USB崩溃与隔离

本机ADB 35.0.2在2026-09-23出现多次 `LibusbConnection::write_cb` / `free_tiny_botch` / SIGABRT，证据为macOS的ADB进程崩溃报告。ADB连接丢失还可使真机测试框架在 `UiAutomation.disconnect` 抛出 `DeadObjectException`；须区分宿主工具、instrumentation和产品代码的失败，不能只看APP进程退出分类。

ADB可选择原生或libusb后端，[官方说明](https://developer.android.com/tools/adb#adb-usb-backends)及[AOSP实现与测试步骤](https://android.googlesource.com/platform/packages/modules/adb/+/a822c059)说明了 `ADB_LIBUSB` 的用法。本机实际用 `ADB_LIBUSB=0` 启用原生后端，`host-features` 已确认不再包含libusb。此处是针对已有崩溃证据的环境处置，不承诺适用于所有ADB版本或操作系统。

默认5037端口可能存在其他客户端竞争。确有工具崩溃且需要隔离时，可只将已授权测试手机从默认libusb服务detach，使用独立5038服务，不修改系统SDK或全局shell配置。先确认该手机无测试运行且其他任务未占用，再执行（`adb` 应指向同一已验证版本）：

```sh
adb -P 5037 detach <测试手机序列号>
ADB_LIBUSB=0 adb -P 5038 start-server
ADB_LIBUSB=0 adb -P 5038 devices -l
ADB_LIBUSB=0 adb -P 5038 host-features
```

项目测试脚本的 `--adb` 可指向本地可执行包装脚本，使全部子命令使用同一服务：

```sh
#!/bin/sh
export ADB_LIBUSB=0
exec "${ROBOT_ADB_BIN:-adb}" -P 5038 "$@"
```

先通过 `ROBOT_ADB_BIN` 指定实际adb路径或保证PATH正确，再赋予包装脚本执行权限。包装脚本放在被Git忽略的目录，不将个人SDK绝对路径提交开源仓库。每轮先分别查询5037/5038的设备清单，后续驱动、诊断和观察器使用实际持有该手机的同一服务，并始终明确序号。归属变化时先保存失败现场并核实原instrumentation，不能直接安装重跑。仅当专用服务没有其他设备/任务且本项目测试结束时，才可停止它并交还默认连接；不要终止其他项目的ADB服务。

使用限制组合测试（与长测串行执行，当前结果与缺口见《自测记录》）：


此脚本与长测共用排他锁，长测仍运行时拒绝占用手机；只安装测试APK，并先核对手机主APK与本地构建SHA256相同。它创建原创音轨，实际跨过一分钟禁用区间，在断网时验证禁止唤醒和解禁不自动播放，再实际耗尽每日额度，终止App进程并离线重开确认额度保留。按实际时间运行，不改系统时钟、不清零原账本。结束恢复原配置、USB连接并下架测试内容；恢复失败保留备份，先用同一命令加 `--restore-only` 重试。仅用于临时测试身份；23:50以后或测试身份当日使用量接近240分钟时不运行本组用例，午夜和系统重启组合另行验收。运行后同时检查逐秒音轨、队列与用量记录；额度达到不能替代音频连续播放证据。系统重启和异常时钟仍需独立验证。

先运行DeviceSmoke建立测试身份，再运行AudioPolicy和MediaCompletion。三类基础真机回归与正式长测、时段额度组合共用排他锁，避免重复安装占用。新版驱动为每轮保存独立 `huawei-<测试类>-<时间>/`，失败也回收可用采样，记录两份APK指纹并拒绝中途构建变化；过时的手机测试文件会在该轮开始前清理，不能拿旧结果冒充新结果。MediaCompletion的延迟/正常两项采样分开保存，按实际MP3元数据校验时长，不写死某个TTS音轨长度。

Qwen合并后，正式长测还固定新TTS模型清单及三个Python依赖锁文件，并在宿主样本中记录服务/TTS进程PID及TTS内存。TTS内存是服务进程树总内存的子集，不要重复相加；固定文件不等于验证所有机器具有相同性能。

- `test_policy_boundaries.py` 结果包含 `network.jsonl`，仅保存脱敏接口路径、状态码／异常类别。连续heartbeat422时先检查App诊断字段与服务契约版本；progress-overflow/rejected/response需要同步的服务版本。不要清空账本来掩盖协议错误。
- `python scripts/tts_concurrency_smoke.py` 用新建测试身份访问实际服务，结束自动撤销该身份；结果只作热态合成、忙碌响应和控制通道验证。需模型预热ready，不在正式手机长测期间并行运行。

### 长测退出与配置恢复

长测仅用于已登记的测试身份。`StabilityTest` 在修改时段、音量和播放计划前，将完整原配置写入手机 Keystore 保护的 Vault；正常或异常退出都通过正式配置接口恢复，收到真实机器人 ACK 后删除备份，再停止采集。恢复失败保留备份并令本轮失败，原始断言仍保留；不能把 workload 的 `complete` 事件单独当作最终通过，必须同时检查 instrumentation 终态及 `configuration-restored`。

进程被强杀时 `finally` 无法保证执行；新测试检测到残留备份会拒绝覆盖。排查连通性后，可在测试工程调用 `StabilityConfiguration.restore()` 重试；没有备份时返回 false，不声称恢复成功。`StabilityConfigurationTest#restoreRecommendedPolicy` 专用于本项目授权的测试手机：先恢复残留备份，再设置20:00—09:00、Asia/Shanghai、每日额度关闭、媒体30分钟、计划关闭、临时放行清零。它是推荐初值设置，不能当成任意家庭原配置恢复工具。

2026-09-23 的旧长测没有备份，已明确按上述推荐初值修复；生产 APK 不变。后续冻结必须包含最新测试 APK，旧长测失败记录不可覆盖或累计时长。
