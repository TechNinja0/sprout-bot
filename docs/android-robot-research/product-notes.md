# Android 陪伴机器人：产品与交互参考研究

资料访问日期：2026-09-21。范围：4 个代表性产品/项目及其官方产品页、支持文档、应用商店说明和开源仓库。本研究是公开资料核查，未购买、安装或实测这些产品；厂商功能描述不作为性能、安全或儿童适用性保证。不是穷尽全网的市场调查。

本文件保留产品事实和来源；已删除被新版替代的点击、字幕及入口设计草案。当前交互以 `../03-App与UI交互方案.md` 和 `../08-双端身份与配对补充方案-v1.2.md` 为准。

## 结论

建议采用“LOOI 的手机承载形态 + EMO/Eilik 的具象表情与短反馈 + Reachy Mini 的能力模块化”作为设计参考，自主实现 Android 应用及原创角色。没有在这组来源中发现可以直接安装、无需专用底座、同时覆盖中文陪伴与自定义移动底盘的完整开源 Android 成品。

“适合约 5 岁儿童”在本次已知用户需求中尚未明确，是可选产品方向，不应自动取代家庭通用陪伴定位。下文儿童模式为本项目建议，不能写成竞品已提供或验证过的能力。

## 1. LOOI：最直接的手机机器人参考

**核实事实。** 官方 Android 应用说明明确利用手机摄像头和算力实现视觉交互，配合语音与表情动作；手机不仅是遥控器。官方 FAQ 明确 App 不能脱离 LOOI 底座独立使用。[官方 Android 应用](https://play.google.com/store/apps/details?id=com.TangibleFuture.looiRobot)、[底座要求](https://looirobot.zendesk.com/hc/en-us/articles/54384992286233-Can-I-use-LOOI-app-without-the-base)

商品页推荐 Android 12+、Snapdragon 8 Gen1+；支持文档还说明低于建议配置可能卡顿。这是 LOOI 的产品要求，不是我们轻量应用的硬性下限。[商品页兼容性](https://looirobot.com/products/looi-robot)、[官方兼容说明](https://looirobot.zendesk.com/hc/en-us/articles/52403657021977-Compatible-Devices)

**隐私资料存在差异。** 2026-08-05 隐私政策说明语音发送给云端服务商、记忆存于云端，可选深度视觉会上传单帧图像；商品页却仍有数据不上云的宣传。设计判断应以详细政策作保守依据，不能宣称它完全离线或数据绝不上云。[现行隐私政策，第 2.4–2.5 节](https://looirobot.com/pages/privacy-policy)

**借鉴到本项目。** 手机正面就是脸；默认画面是角色而非聊天记录；表情、声音、动作由同一状态驱动。固定支架即可先运行完整桌面软件，后续底盘能力通过独立模块适配。

**不照搬。** 不复制其眼睛造型、动画、音色或专有底座协议；不承诺它宣传的动作数量。其美国区 Google Play 当前显示 Teen 分级，不能把“造型可爱”当成适合幼儿的证据。若选儿童模式，必须另做内容范围、家长控制及退出机制。

## 2. EMO：行为连贯与陪伴感参考

**核实事实。** 厂商介绍涵盖面部识别、声音定位、头部触摸、表情和身体动作，以及生日等场景反馈。它使用专用机器人硬件，手机 App 是配套工具；不是手机充当主控的方案。产品页部分项目明确标记未来功能，不能全部作为已交付能力。[EMO 官方产品页](https://living.ai/emo/)

**借鉴到本项目。** 让角色在等待时有低频眨眼、轻微视线变化；听到唤醒时先看向用户并给出提示，结束时自然回到待机。生日等仪式感应由本地配置和可预测规则触发，不依靠大模型随机决定。

**不照搬。** 不把“有情绪”的表达包装成它具有真实感受，也不采用生病、被抛弃、责怪用户等索取持续陪伴的机制。机器人不应要求孩子照顾它才能恢复功能。手机没有 EMO 的麦克风阵列，不能把视觉转头等同于真实声源定位。

**资料局限。** 未进行防跌落、识别率或长期运行验证；本次未完成其音视频数据路径核查，因此不对其隐私作肯定判断，也不把“永不掉下桌子”等宣传转化为验收标准。

## 3. Eilik：低复杂度、即时反馈参考

**核实事实。** Eilik 官方介绍强调触摸、震动和被拿起时的表情反应。官方地区商店对 Silver 本体明确说明不支持 AI 语音交互；这一结论不能延伸到后来加入的 AI Station 或 Eiliko 系列。[Eilik 产品介绍](https://www.energizelab.com/eilik/)、[Eilik Silver 说明](https://ae.energizelab.com/pages/eilik-silver)、[产品支持分类](https://www.energizelab.com/support/)

**借鉴到本项目。** 借鉴即时表情反馈与讲故事时随语气变化的表现；具体操作以当前 UI 方案为准。基础触摸反馈应离线可用，在模型接口不可用时依然像一个可互动的小设备。

**不照搬。** 不将预设动画误称为大模型情绪理解；不模拟受伤、惊吓或惩罚儿童的交互。不把肢体部位触摸照搬成手机页面上的隐形手势：必要入口必须有可发现提示。

**资料局限。** 这是专用硬件产品，并未据本次资料核实到可直接复用的 Android 完整源码。网站有新旧产品信息共存，不宜泛称“Eilik 全系列都没有 AI”。

## 4. Reachy Mini：开放架构与动作组织参考

**核实事实。** 官方文档区分 Wireless（机载 Raspberry Pi CM4）和 Lite（连接电脑）版本，提供会话应用及手部跟踪等示例。SDK 有 Python 和 JavaScript/WebRTC 路线，并非现成 Android 手机机器人 App。[官方文档](https://huggingface.co/docs/reachy_mini/index)

仓库软件使用 Apache-2.0；官方同时将硬件设计文件标为 CC BY-SA-NC，不能把软件许可套用到所有机械文件、资源和第三方 App。[仓库](https://github.com/pollen-robotics/reachy_mini)、[软件 LICENSE](https://github.com/pollen-robotics/reachy_mini/blob/main/LICENSE)

**借鉴到本项目。** 把“开心点头”“倾听”“休息”等定义为语义动作，由 Android 屏幕渲染器或未来舵机适配器执行；对话逻辑不直接操作电机。为每个动作配置持续时间、幅度和优先级。触摸停止、过热和断连始终可以中断表达动作。

**复用边界。** 可以研究并按具体许可证复用适合的会话、状态管理和动作调度思路；不能认为将 SDK 编译进 Android 就能驱动任意自制底盘。现有手机 App 仍需自行完成 Android 音频、CameraX、生命周期、UI 与 BLE/USB 适配。

## 研究边界与待验证项

- 资料来自官方公开陈述，未测试中文识别、响应延迟、断网行为、耗电或稳定性。
- LOOI 兼容配置和隐私描述在不同官方页面存在粒度差异，采购或选型前应以具体机型和当期 App 实测为准。
- 未将旧众筹承诺、用户评论或市场宣传作为能力已实现的独立证据。
- 不采用竞品截图或现有角色资产作为交付 UI；角色、图形、音效和文案需原创或有明确可用许可证。
- 手机型号未知，目前只能设计分级能力和验证方法，不能保证某台旧手机一定支持全双工打断或持续视觉跟踪。
